# OpenJiuwen Budget-Aware Agent

Харнесс для соревнования Budget-Aware Token Estimation for Agentic AI. Он читает каталог задач, оценивает ожидаемую награду на единицу расхода и публикует проверенные ответы по мере решения. Каждая попытка выполняется через `AgentApp` openJiuwen.

## Сборка и запуск

Из корня репозитория, на Linux с Docker:

```bash
docker build -t hack:latest .
docker images hack:latest --format '{{.Repository}}:{{.Tag}} -> {{.Size}}'
```

Базовый образ Python 3.13 Slim закреплён по digest. Версии зависимостей и ревизии openJiuwen зафиксированы в `requirements.lock`. Пакеты устанавливаются при сборке. Во время запуска обращения к модели идут через прокси организаторов.

Перед запуском задайте на хосте переменные из таблицы. Команда использует сеть `hack-net`, подготовленную организаторами. Для локального прогона используйте сеть, через которую доступен ваш прокси.

| Переменная | Назначение |
|---|---|
| `TASKS` | Абсолютный путь на хосте к каталогу задач. В контейнере он монтируется в `/data/tasks`. |
| `LLM_BASE_URL` | Адрес OpenAI-совместимого прокси, с суффиксом `/v1` или без него. |
| `LLM_API_KEY` | Ключ прокси, предоставляемый при запуске. |
| `BUDGET` | Выданный на прогон бюджет в конкурсных токенах, положительное целое. Значение может отличаться между прогонами. |
| `TEAM` | Имя для Docker-контейнера. |

```bash
timeout -k 1000s 1h docker run --rm --name "run-${TEAM}" \
  --network hack-net \
  -e LLM_BASE_URL -e LLM_API_KEY -e BUDGET \
  -v "$TASKS:/data/tasks:rw" \
  --read-only --tmpfs /tmp:rw,size=2g -e HOME=/tmp \
  --cap-drop ALL --security-opt no-new-privileges \
  --cpus 4 --memory 16g --pids-limit 512 \
  --workdir /app --entrypoint python hack:latest \
  /app/run_agent.py --tasks-dir /data/tasks
```

Модель по умолчанию — `qwen3.8-27b`. Для явного выбора разрешённой модели есть `--model` и `MODEL_NAME`. Параметр `--budget` переопределяет `BUDGET` при ручном запуске. При отсутствии обоих значений локальный общий лимит отключён, а лимиты попыток и общий дедлайн 3590 секунд продолжают действовать.

## Вход и результаты

В `--tasks-dir` находятся каталоги задач с `task.json` и входными файлами в `workspace/`. Харнесс использует тип задачи, условие, награду и формат проверки. Для каждого принятого решения он сразу записывает `<каталог задачи>/answer.txt`. Для программирования сначала публикует проверенные правки исходников в `workspace/`, затем записывает `DONE`. Это формат публикации по явной команде и уточнению регламента о файле `answer.txt` в каждой задаче.

Для свежего прогона используйте копию входного каталога без существующих `answer.txt`. Готовый файл ответа означает, что задача уже обработана, и агент её пропускает.

## Оценка расхода и выбор задач

Перед модельными вызовами харнесс оценивает стоимость и вероятность успеха по типу задачи, длине инструкции, количеству и размеру файлов. Приоритет равен награде, умноженной на вероятность успеха и делённой на оценку расхода. Для небольших Python-задач оценка корректируется по медиане успешных попыток текущего прогона. При наличии остатка бюджета возможна ограниченная попытка.

Расход в целых единицах равен `input_tokens + 10 × output_tokens`. Десять единиц равны одному конкурсному токену. Учитываются все входные токены и токены рассуждений как часть выхода. Перед запросом резервируются оценка входа и лимит выхода, после ответа используется `usage`. Если точного `usage` нет, учитывается оценка. Профиль по умолчанию `included` использует `completion_tokens` как полный выход. Для API с отдельным счётчиком рассуждений доступен `--usage-profile separate`.

## Невыполнимые задачи и проверка

Распознанные задачи харнесс сначала пробует решить локально. Отсутствие обязательного файла или недостающая запись в поддерживаемом формате базы могут привести к раннему пропуску. В общем маршруте агент может отказаться при недостаточных или противоречивых данных. Лимиты контекста, шагов и повторов ограничивают расход при отсутствии прогресса. Для ответов общего маршрута проверяются формат и ссылка на успешный вызов инструмента.

Для Python-задач запускаются исходные публичные тесты. При наличии `SPEC.md` агент читает её до правок и подтверждает завершение отдельно после проверки требований. Исполнение Python и тестов требует Landlock ABI 3 и seccomp. Если проверка изоляции не проходит, харнесс отключает исполнение и пропускает Python-задачи.

## Траектории и локальная проверка

Стандартный вывод содержит JSONL. `task_estimated` показывает оценку до решения, `task_selected` — выделенные лимиты, `task_finished` — результат и расход попытки. `model_usage` и `run_finished` содержат накопительный и итоговый расход соответственно. Для подробной траектории добавьте `--attempt-history` и сохраните stdout в файл. В ней фиксируются вызовы модели и инструментов, проверка кандидатов и публикация. Сумма `model_request_finished.seconds` измеряет время ожидания запросов к API со стороны агента. `run_finished.seconds` измеряет весь прогон.

На трёх локальных слепых прогонах было получено 20/20, 228/229 и 206/209 баллов. Во всех использовались `qwen3.8-27b` и бюджет 100 000 конкурсных токенов на набор. Суммарно ожидание 566 запросов к API заняло 48 мин 36 с, а расход составил 154 710,4 конкурсного токена. Часть расхода четырёх запросов с ошибками рассчитана по оценке. Локальная оценка использовала эталоны и исходные публичные тесты после выполнения.

Проверка интеграции через openJiuwen с имитацией прокси:

```bash
docker run --rm --network none --read-only --tmpfs /tmp:rw,size=2g \
  -e HOME=/tmp --cap-drop ALL --security-opt no-new-privileges \
  --entrypoint python hack:latest -m scripts.check_runtime
```
